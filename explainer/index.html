Why DeskCam? General Utility & Hardware Economics

Almost every engineer has an old smartphone sitting unused in a drawer. At the same time, standard USB webcams used on workbenches suffer from severe optical deficiencies:

  • Webcams are physically inadequate: Cheap USB webcams have tiny, noisy 1/4" sensors, fixed plastic lenses, severe chromatic aberration, and hunting autofocus routines that fail on circuit boards.
  • Webcam drivers are bloated: Most webcams require heavy drivers, lack manual exposure locking, and silently apply non-linear tone curves that destroy optical truth.
  • A smartphone is an optical supercomputer: A modern phone contains a large Sony IMX sensor with high quantum efficiency, 10-bit linear RAW output, voice-coil motor autofocus, a 45-level LED torch, multi-core CPU/GPU, battery backup, and high-speed Wi-Fi/USB.

AI Agent Access & Image Capture

Traditional camera software is designed for human eyeballs clicking glass buttons. When an AI agent (such as Claude Code or an autonomous coding assistant) interacts with a camera, traditional video streams or GUI-based controls fail completely.

The 8 Agentic Design Rules (R1–R8)

DeskCam's architecture adheres strictly to eight rules designed specifically for language model agents:

Rule Design Principle Why It Matters for AI Agents
R1 Exit codes over prose Every command exits 0 for success, 2 for a valid refusal (e.g. noise floor failure), and 1 for tool error. Agents branch on numeric exit codes, not ambiguous text parsing.
R2 Print paths, never pixels A capture command outputs exactly one file path to stdout (/tmp/deskcam-01.jpg). The agent reads the file with dedicated vision tools, keeping the LLM prompt context clean.
R3 Full k=v on every endpoint Any endpoint accepts the full control set. The agent does not need to query state or manage sessions before acting: deskcam snap zoom=4 cx=0.3 exposure=1/120 is an atomic unit of intent.
R4 Report measured truth Responses return the actual achieved hardware settings from the sensor's TotalCaptureResult, not just requested values. The agent verifies reality in the same request.
R5 Unknown parameter is HTTP 400 A spelling mistake fails immediately with HTTP 400. It never silently defaults or falls back, preventing the agent from trusting an incorrectly framed or exposed capture.
R6 The API describes itself GET /api/help returns the machine-readable schema generated directly from Params.java. The agent queries the live endpoint to learn valid ranges without stale docs.
R7 Native datasheet units Parameters accept datasheet units directly: 1/120, 8ms, 250us, 0.12m, or dioptres. The agent executes zero unit conversions.
R8 Pure idempotence Re-running any command with identical parameters safely produces the same hardware state. Duplicate agent retries never cause state drift.

Closed-Loop Autonomous Focus Hunting

Closing an autofocus loop across a Wi-Fi network requires 14 round trips: set focus → wait settle → request frame → compute sharpness metric. Over the network, this takes over 15 seconds.

DeskCam solves this with /api/focushunt. The phone runs the search loop in-camera on the live NV21 preview stream: it conducts a 9-step coarse search followed by a 5-step fine search, computing the Laplacian variance of each frame in ~9 ms. The entire search finishes in 4.0 seconds, transferring zero intermediate frames over the network.

5-Minute Setup & Quick Start Guide

Getting DeskCam running on your bench requires only a few commands. The Android app has zero external dependencies and builds in approximately 2 seconds.

Prerequisites

  • Any Android device supporting Camera2 API (Android 10+; optimized for Pixel 6a on GrapheneOS / Android 17).
  • Workstation running Linux or macOS with Go and Android SDK build-tools installed.
  • USB-C cable (for adb) or shared Wi-Fi subnet.

Step 1: Build & Install the Phone App

# Clone the repository
git clone https://github.com/mattjoyce/AndroidDeskcam.git
cd AndroidDeskcam

# Compile the zero-dependency APK directly using Android SDK tools (~2.1s clean build)
./backend/build.sh

# Install onto your phone via USB with runtime permissions auto-granted (-g is essential!)
adb install -r -g backend/build/deskcam.apk

# Launch the camera foreground service headlessly
adb shell am start -n dev.deskcam/.MainActivity -a dev.deskcam.START --ez finish true
⚠️ The Android 17 Local Network Gotcha

In Android 17 (API 37), local network access is completely separated from the INTERNET permission. An app can reach the public internet while the OS silently drops all incoming and outgoing LAN packets. The -g flag in adb install -r -g ensures the critical android.permission.ACCESS_LOCAL_NETWORK is granted immediately.

Step 2: Build the Static Go CLI

Compile the workstation CLI. It produces a single, self-contained binary with no runtime dependencies: 

cd frontend/go
go build -o deskcam .
cd ../..

# Symlink to your PATH for instant access
ln -s "$PWD/frontend/go/deskcam" ~/.local/bin/deskcam

Step 3: Connect to the Phone

# Option A: Zero-configuration USB loopback (bypasses all Wi-Fi & permissions)
deskcam usb          # executes 'adb forward' to 127.0.0.1:8080

# Option B: Wi-Fi on local subnet
deskcam wifi         # discovers phone IP on your local subnet

# Verify connection:
deskcam show         # prints one-line status summary

Technical Architecture & Software Components

DeskCam strictly enforces a three-tier separation of concerns (Decision D13). Each language is selected for technical necessity rather than convenience:

Deep Dive: The Backend Java Daemon

The phone runtime is built from scratch without standard Android app bloat:

  • HttpServer.java (~400 lines): A lean, multithreaded HTTP/1.1 server running on a raw ServerSocket. It handles keep-alive connections, serves MJPEG multipart streams, and dynamically formats USTAR tar archives in memory.
  • CameraEngine.java: Controls the Camera2 hardware capture session. It coordinates two pipelines: a repeating preview stream (YUV_420_888 → NV21) and on-demand full-resolution still captures.
  • TotalCaptureResult Correlation (Decision D8): Every frame request is paired with its hardware capture result using the sensor's hardware timestamp clock, guaranteeing that EXIF metadata and sidecars reflect the true physical capture.

Deep Dive: The Static Go Binary (frontend/go/)

Taking a photograph or checking camera status requires zero runtime dependencies. The Go CLI is compiled into a single static binary:

  • Zero-Config URL Discovery: Automatically resolves the camera target in priority order: --url flag → $DESKCAM_URL environment variable → ~/.config/deskcam/url → localhost:8080.
  • Automated USB Forwarding: deskcam usb executes adb forward tcp:8080 tcp:8080, making camera control 100% reliable even in air-gapped or restricted Wi-Fi environments.
  • Integrated Web Console: deskcam serve runs a local web viewfinder with live MJPEG streaming, touch-to-center pan/zoom, and thumbnail rolls.

Sensor Physics: Software ROI Pan vs HAL Center Zoom

The Pixel 6a sensor reports android.scaler.croppingType = CENTER_ONLY. When the camera HAL receives a crop rectangle with an offset, it strips the offset and zooms strictly around the optical center. Hardware pan is physically impossible on the device.

The Solution (Decision D1): DeskCam always requests the full, uncropped 4032 × 3024 12MP array from the sensor. Cropping to the target Region of Interest (ROI) is executed entirely in software. Every pixel in a zoomed image remains a true, un-interpolated sensor pixel. Autofocus and auto-exposure metering regions dynamically follow the software ROI.

Macro Optics: Dioptres vs Millimetres

When sweeping or stacking focus across close subjects (such as SMD IC leads), stepping the lens in millimetres causes non-linear blur discs. Depth of field (DOF) is nearly constant per dioptre ($D = 1/f$ in metres), whereas in millimetres it changes quadratically:

  • At the 98 mm minimum macro focus, 1 mm corresponds to ~0.10 dioptres.
  • At 500 mm distance, 1 mm corresponds to ~0.004 dioptres (a 25× difference!).

A focus sweep evenly spaced in millimetres would step completely over a close-up subject while crawling uselessly at distance. DeskCam sweeps (deskcam focussweep) are spaced evenly in dioptres.

Display Engineering: PWM Rolling Shutter Anti-Banding

OLED displays and LED work lights are driven with Pulse Width Modulation (PWM), typically at 240 Hz, 360 Hz, or 480 Hz. Because CMOS sensors expose row-by-row via a rolling shutter, an arbitrary exposure time (such as 1/100 s = 2.4 periods at 240 Hz) causes each row to integrate a different duty-cycle phase, creating bright and dark horizontal bands.

The Power-of-Two Bracketing Rule: To capture multi-exposure HDR brackets of an illuminated display without banding, DeskCam anchors the base exposure to exactly one PWM period (e.g. $1/240 ext{ s} pprox 4.17 ext{ ms}$) and steps strictly in powers of two ($1/240$, $1/120$, $1/60$, $1/30$). Every exposure remains an integer multiple of the PWM cycle, completely neutralizing phase banding.

Action Tape DSL: Atomic Hardware Execution

Multi-step sequences driven via ad-hoc shell loops are fundamentally racy: a secondary agent or an open web console tab polling /api/status can alter camera settings between a SET and a SNAP.

DeskCam solves this with POST /api/script. An execution tape runs atomically on the phone:

  • Atomic Camera Lock: While a tape executes, any concurrent request attempting to alter camera state is rejected with HTTP 409 Conflict. (Read requests remain permitted).
  • Zero On-Device Storage: The response is a single multipart/mixed HTTP stream. Step completion events (JSON) and captured image parts (JPEG/TAR) stream back down the same TCP socket. The phone stores nothing.
  • Execution Tape, Not a Language: Tapes contain no variables, branching, or loops. The agent provides the intelligence; the tape provides the execution record.

The Complete HTTP API Contract

The HTTP contract is the sole interface between the workstation and the phone. With the exception of POST /api/script, all operations are simple HTTP GETs, allowing direct execution via curl, shell scripts, or agent HTTP clients.

Method & Endpoint Response MIME Description & Invariants
GET /api/status application/json Returns full camera state, sensor limits, thermal throttling levels, and preview exposure metrics. sharpness=1 triggers fresh Laplacian evaluation.
GET /api/still image/jpeg Full 12MP resolution crop to ROI. If zoom ≤ 1.0001 and no rotation, returns untouched camera JPEG; otherwise tiled decode/encode.
GET /api/raw image/x-adobe-dng 10-bit linear Bayer RAW DNG containing full uncropped 4032×3024 array. Header X-DeskCam-ROI carries active framing.
GET /api/burst application/x-tar Burst of n frames submitted back-to-back in a single HAL request. Returns HTTP 206 Partial Content if fewer frames delivered.
GET /api/focushunt application/json Coarse (9 steps) + Fine (5 steps) search on phone. Returns chosen dioptres and full sharpness curve. Returns ok: false on flat/edge curve.
GET /api/focussweep application/x-tar Steps lens equally in dioptres from from to to. Archive contains all JPEGs plus walk.json manifest.
GET /api/bracket application/x-tar Multi-exposure bracket stepping in powers of two from base period. Sidecars record actual delivered exposure vs requested to 0.01 periods.
GET /api/stream multipart/x-mixed-replace Live MJPEG viewfinder stream. Accepts only fps, n, w, h. Sheds rate automatically when phone is hot.
POST /api/script multipart/mixed Executes plain-text tape of verbs atomically. Rejects concurrent camera writers with HTTP 409 Conflict.
GET /api/orientation application/json Average angle between optical axis and gravity vector over 32 samples, plus ambient lux.
GET /api/help application/json Machine-readable schema and documentation generated directly from Params.java.

Metrology & The Philosophy of Refusal

The analysis tools in frontend/analysis/ operate 100% offline, consuming saved images and sidecar JSON metadata from disk. They enforce a strict empirical discipline:

🚫 The Rule of Scientific Refusal

A measurement refuses rather than guesses. Printing a number with an unread caveat fails, because caveats are discarded downstream. Every tool computes its value, sample count, confidence interval (e.g. 95%), and metric bound. If the data fails the threshold, the tool refuses to output a value and exits with code 2.

Tool Target Metric Confidence Parameter Rejection Gate Scientific Rationale
aatest Instrument Noise Floor Fraction of unpinned pixels < 0.99 non-pinned Clamped pixels (0 or 255) show zero difference, artificially flattering the noise floor calculation.
linearity Sensor Gamma & Pedestal Power-law fit R² R² < 0.980 Both linear response and sRGB curves fit above 0.99; ensures sensor gamma is truly 1.0 with ~2 DN black offset.
scale Spatial Resolution (px/mm) Autocorrelation peak height Peak < 0.60 Real ruler tick marks produce peaks from 0.76 to 0.96; harmonic false matches land around 0.33.
burst-noise 1/√N SNR Scaling Interval tightness Tightness < 0.85 Distinguishes true photon noise reduction from JPEG compression artifacts or fixed-pattern noise.
hdr Absolute Radiance (DN/s) Inter-frame consistency Residual > 3% Adjacent exposure brackets must report equal radiance; rejects frames corrupted by PWM phase beating.

Architectural Decisions (D1–D16)

Decision D1 Optics
Software ROI Cropping
Because the HAL only zooms from center (CENTER_ONLY), software always pulls the full 12MP array and crops in memory, enabling panning with 1:1 true pixels.
Decision D3 Protocol
All Operations are GET
Optimizes for the primary consumer: shell scripts and agent tools. Any action is callable via a single curl or URL without JSON wrapping.
Decision D8 Metrology
Captures Describe Themselves
Every capture carries its own CaptureCallback and correlates result by sensor timestamp. Provenance travels inside image EXIF and HTTP headers.
Decision D9 Lifecycle
Tri-Partite Parameters
Divides parameters into: Camera State (persists: zoom, focus, exposure, rotate), Presentation (one request: w, h, jpegq), and Router (settle, fresh, timeout).
Decision D13 Toolchain
The Three-Language Seam
Java on phone for framework classes; Go for a single zero-runtime workstation CLI binary; Python exclusively for NumPy metrology array math.
Decision D14 Concurrency
Script Holds Camera Lock (409)
Execution tapes hold exclusive write access to prevent web console or secondary agent race conditions. Streams multipart events and byte parts back down TCP socket.
Decision D15 Thermal
Stream Sheds, Capture Never Does
When phone hits severe thermal status, MJPEG frame rate is dropped to 1/4. Captures are never altered or slowed, preserving scientific exposure timing.
Decision D16 Power
Idle Sensor Shutdown
Halts repeating preview request after 20 seconds of inactivity. Wakes on demand, guaranteeing 4 discarded frames for 3A convergence before taking a picture.
